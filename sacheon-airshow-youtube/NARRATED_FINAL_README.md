# 준호 내레이션 최종본 — 기존 영상 사운드·자막 개선

기존 60초 임시본의 취재 사진·캐릭터·장면 순서·카메라 움직임을 유지하고,
기존에 렌더링한 장면 클립을 재사용했습니다. 새 사진이나 캐릭터를 생성하지
않았습니다. 기존 MP4·사진·오디오 원본은 그대로 보존합니다.

## 최종 결과

`output/narrated_final/sacheon_trailer_junho_60s_1080p_24fps_FINAL.mp4`

- 영상·오디오·컨테이너 모두 정확히 60.000초
- 1920×1080, 16:9, 24fps, 1440프레임, H.264 MP4
- AAC, 48kHz, 스테레오
- 제공된 준호 내레이션·두 종류의 Mixkit 효과음·기존 시네마틱 음악 포함
- 실제 발화에 맞춘 한국어 자막 19개 구간, 하단 중앙·흰색·외곽선
- 별도 `sacheon_trailer_junho_60s_24fps.srt` 제공

`verification_junho_final.json`, `independent_qa.json`에 실제 검증 결과가 있습니다.
`contact_sheet.jpg`는 렌더 프레임 검수표이며 `delivery_manifest.json`은 파일 해시입니다.
기존 임시본의 TEMP 표시는 제거하고 `AI 내레이션 · 준호`로 표시했습니다.

## 실제 입력과 편집

세 파일 모두 `assets/`에서 직접 읽었습니다.

| 원본 | 확인한 길이 | 사용 |
| --- | --- | --- |
| `narration.mp3` | 컨테이너 53.890563초 / 48kHz 디코드 53.890625초 | 영상 3.000–56.890625초, 전체 샘플 유지 |
| `mixkit-aircraft-flyby-3170.wav` | 10.000초 | 실제 취재 사진 구간에서 한 번, 왼쪽→오른쪽 통과 |
| `mixkit-jet-plane-flying-rumble-1587.wav` | 14.102993초 | 검은 오프닝·KF-21 설명 그래픽 진입 |

목소리는 속도·높낮이·발화 길이를 바꾸지 않았습니다. 적용한 처리는 통상적인
샘플레이트 변환, 음량과 피크 제어뿐입니다. 원본 전체를 3초부터 놓아 파일 끝까지
유지했고, 약 3.109초의 엔딩 여유를 확보했습니다.

음악·효과음은 실제 음성 에너지에 반응해 부드럽게 줄어듭니다. 발화 시 음악은
최대 14dB, 효과음은 최대 18dB 낮추고 쉼에서는 회복합니다. 음성 종료 후 음악을
올렸다가 마지막 0.8초에 자연스럽게 페이드아웃합니다. 동일 flyby는 한 번만 사용합니다.

| 음향 사건 | 영상 시간 |
| --- | --- |
| 엔진음 서서히 상승·검은 화면 | 0.000–3.800초, 화면은 0–3초 검정 |
| flyby 전체 구간 / 통과 피크 | 15.308–22.358초 / 17.358초 |
| KF-21 설명 그래픽·엔진음 | 21.458–26.058초 |
| 내레이션 전체 | 3.000–56.891초 |
| 음악 엔딩·제목·크레딧 | 음성 종료 후–60초 |

제공 취재 사진에서 KF-21을 확실히 식별하지 못했던 기존 판단을 유지했습니다.
KF-21은 별도 설명 그래픽으로 표시하고 다른 기종 사진에 KF-21 이름을 붙이지 않습니다.
AI 조종석·실제 취재 사진·개념 그래픽 구분과 사진 크레딧도 유지합니다.

## 한국어 자막 동기화

실제 녹음이 기존 임시 대본과 달라 녹음의 내용으로 자막을 교체했습니다.
무료 로컬 sherpa-onnx Whisper base 다국어 모델의 발화 시점과 실제 에너지·쉼을
결합했습니다. 문장별 구간도 독립적으로 재인식했습니다. 19개 구간은 글자 수를
기준으로 시간을 나눈 결과가 아닙니다.

사천에어쇼·블랙이글스·보라매·기종명·임무 등 음성 인식의 고유명사 오기와 띄어쓰기를
문맥에 맞게 정리했습니다. 자막은 원본 음성 기준에 3초를 더합니다.
`cinematic/junho_alignment.json`은 원본 음성 SHA-256을 검사하므로 다른 녹음에는
그대로 적용하지 않습니다. 음성 인식·에너지 검수는 사람의 모든 음소 청취 인증과는
다르며 검수 방법과 근거를 보고서에 기록했습니다.

추가 비용이 드는 API 호출이나 외부 음성 업로드는 없었습니다. PyTorch도 설치하지
않았습니다. ONNX 모델과 실행 환경은 `work/`에만 두고 저장소에는 게시하지 않습니다.

## 재실행

기존 Python·FFmpeg/FFprobe·Pillow·NumPy·SciPy 환경에서 저장소 루트 기준:

```bash
python3 sacheon-airshow-youtube/scripts/finalize_narrated.py \
  --alignment sacheon-airshow-youtube/cinematic/junho_alignment.json \
  --timeline sacheon-airshow-youtube/cinematic/junho_timeline.json \
  --output-dir /path/to/a/new/output
```

기존 장면 캐시를 우선 사용합니다. 캐시가 없는 다른 환경에서는 함께 제공한
`output/narrated_final/reused_scene_cache.zip`의 동일 장면 8개를 읽습니다.
기존 음악 WAV가 없으면 기존 임시 MP4의 음악을 읽습니다. 새 영상 자료를 만들지
않습니다. 다른 출력 폴더를 지정하면 이번 최종본도 보존하며 재실행할 수 있습니다.

제작 진입점은 `scripts/finalize_narrated.py`, 사운드 모듈은
`cinematic/final_audio_mix.py`, 실제 발화·장면 타임라인은
`cinematic/junho_alignment.json`, `cinematic/junho_timeline.json`입니다.
